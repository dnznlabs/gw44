# m01-t01 — handoff

PR: #8 · Branch: `m01/t01-ci-engines` · 2026-11-20

The e2e suite stopped hunting for a Chromium binary and now launches whichever engine `GW44_ENGINE` names, with `make e2e` running it once per name in `ENGINES` and stopping at the first failure; a name that is not one of the three fails at module load rather than falling back. `.github/workflows/ci.yml` runs the whole-tree secret scan, the typechecks and unit tests, then the suite in Chromium, Firefox and WebKit, and fails if anything dirtied a tracked file. Step 6 — "make the two new engines pass" — turned out to need no product changes at all: once Firefox and WebKit could launch, they passed every case the plan's one known skip does not cover, so nothing under `src/` is touched by this PR.

## Deviations from the plan

1. **`devbox-version` is `0.22.0`, not the `0.18.0` step 5 specifies.** At `0.18.0` the action rewrote `devbox.lock`'s `nodejs@24` `plugin_version` from `0.0.6` to `0.0.4` and the working-tree check failed the run — correctly. The committed lock was written by devbox `0.22.0`, which is what this VM runs, so `0.18.0` and the lock disagree. Re-locking under `0.18.0` would only move the problem, because the next local `devbox` command writes `0.0.6` back and dirties the tree for whoever commits next. Aligning CI to the lock is the one change that leaves both sides stable. The reason is in a comment above the step.
2. **The e2e step sets `PLAYWRIGHT_SKIP_VALIDATE_HOST_REQUIREMENTS=1`,** which step 5's list does not mention. Without it Firefox and WebKit never launched in CI even though `--with-deps` had installed their libraries successfully — see § Discoveries 1 for the measurement. The libraries are present; only Playwright's pre-launch check is wrong, so the check is skipped and the launch itself is still free to fail.
3. **The skip is `test(name, { skip: reason }, fn)`, not `test.skip`.** Step 3 asks for "`test.skip` with that reason in the call". In `node:test` the `test.skip()` form takes no reason, so it cannot satisfy the rest of the sentence; the options object is the form that carries one and prints it as a `#` directive after the test name, which is what criterion 2 reads. Same effect, different spelling.
4. **Step 1's check destroyed the directory it moved aside instead of restoring it.** `npx playwright-core install` treats an unreferenced cache directory as garbage and printed `Removing unused browser at …/chromium_headless_shell-1243.aside`, so `1243` is gone rather than put back. It is a regenerable download and `1255` is the pinned build the suite now uses, but the check as written cannot be run twice without re-downloading.
5. **Two commits on the branch are an investigation, not a change.** `7294433` added a temporary diagnostic step to the workflow and `6d97a53` removed it again; their net effect on the tree is nothing. They are kept rather than squashed because the runs cited in § Discoveries 1 belong to those commits, and the evidence is worth more than a tidy history.

## Decisions

- **`ENGINES` is one list, read by both `make browsers` and `make e2e`.** The alternative was a separate variable for installing, which would let the installed set and the tested set drift — and the failure that causes, an engine named but never downloaded, is one the plan explicitly wants reported rather than skipped.
- **The engine name is validated at module load, not inside a hook.** A bad name then fails before any server or browser starts, so `make e2e ENGINES=nope` cannot be mistaken for a test failure, and the message names the three valid values.
- **The default stayed `ENGINES=chromium`.** `make check` is what a contributor runs; defaulting to three engines would fail on every machine without the system libraries, which is every machine the project currently develops on.

## Discoveries

1. **Playwright's host check runs `ldd`, and inside devbox that is nix's `ldd`, which cannot see apt's libraries.** Measured on the runner: outside devbox, `ldd` on the Firefox binary reports **0** `not found` and `ldconfig -p` finds the libraries; inside devbox, `ldd` is `/nix/store/…-glibc-2.44-57-bin/bin/ldd` and the check reports every library missing. So `--with-deps` works and the browsers run; only the pre-launch validation is wrong. This will bite any future step that runs a prebuilt FHS binary through `devbox run --`.
2. **Firefox and WebKit needed no product changes.** Step 6 budgeted for defects in `src/adapters/sw/`, tests that assumed Chromium, and engine limits. There were none: both engines passed all 8 non-CDP cases first time. The service worker, the inline fallback and the host form work in all three engines as written, which is the first evidence for the two engines [spike 001](../../../../spikes/001-static-gateway.md) § Not measured lists. Caveat worth keeping: this is headless Firefox and WebKit under Playwright, not Safari on a device.
3. **Open question 1's default cost less than the plan expected.** The recommendation was to install the libraries locally because "step 6 is where this task's time goes". Step 6 cost **two** CI runs and no code, so the local loop would have saved little. The libraries are genuinely absent here — `ldconfig -p` finds none of `libasound.so.2`, `libgtk-3.so.0`, `libdbus-1.so.3` — and Firefox wants 18 of them, WebKit more. Recorded in `AGENTS.md` § Gotchas as the plan asks.
4. **`devbox.json`'s `$schema` pins `0.18.0` while `devbox.lock` was written by `0.22.0`.** Pre-existing, unrelated to CI, and not touched here. The schema URL only drives editor validation, but the two should probably agree.
5. **The e2e suite's no-service-worker case is 4.4 s of the 5.7 s run** and that is by design (`AGENTS.md` § Gotchas). It is now paid three times, once per engine, so `make e2e ENGINES="chromium firefox webkit"` spends about 13 s waiting out `WORKER_MS`. Worth knowing before m01-t02 adds cases.

## Open questions

None. Open question 1 took its stated default — no libraries installed on the development VM — which the plan says gates nothing; § Discoveries 3 reports what that default actually cost, in case it informs m01-t02.
